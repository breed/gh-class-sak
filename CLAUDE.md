# project description

a swiss army knife for managing github classrooms now the official github classrooms is gone.

# language

- python to be deployed via pypi
- click for commandline parsing

# testing

- pytest, run with `pytest`. install the dev extra with `pip install -e ".[dev]"`
- github and canvas are stubbed in `gh_class_sak/fakes.py` (the `demo` command runs on them too; `tests/fakes.py` re-exports them), so the suite runs offline. never let a test reach the network. the docs' invented course is `gh_class_sak/demo.py`, and `demo_world()` there is the one offline setup the demo command, the doc replay test, and the demo cast share
- when fixing a bug, reproduce it first and add a failing test before the fix

# repo hygiene

- this project follows the "repo to product" tips. the `repo-audit` and `repo-upgrade` skills from https://github.com/breed/repo-to-product are the source of truth
- run `repo-audit` before a release and after any change to packaging, docs layout, or CI
- keep docs in the Diátaxis layout the skill expects: tutorial, how-to, reference, explanation

# common flags

- `--help` lists commands in usage order, not alphabetically: groups use core.UsageOrderGroup with an explicit `order` (setup first: help-me-setup, course, assignment, sync, …; course: init first). a new command must be added to its group's order, or it lands after the named ones

- slow per-repo/per-person loops iterate through `core.progress(items, label)` — a stderr progress bar that is a plain passthrough when stderr is not a tty, so pipes, fences, and tests see nothing. while a bar is up, `error`/`warn`/`info`/`output` hold the message and flash it at the end of the bar's line, where it stays until the next message replaces it; everything prints for real — colors, streams, and order intact — when the bar finishes; a nested bar hands its held messages to the outer one
- for commands that change something, use a `--dryrun/--no-dryrun` flag pair defaulting to dryrun. the bare command just prints what would happen with a ⚠️ in front; `--no-dryrun` applies the change. `--apply` is a synonym for `--no-dryrun` (core.DRYRUN_FLAGS), and the messages suggest it. a dry run announces itself first: `⚠️  dry run: no changes will be made. add --apply to make them`, and — when it printed any would-line — ends with `⚠️  that was a preview: nothing changed. add --apply to make these changes`; the renamed meta commands keep the old `add --no-dryrun to apply` banner (both implemented centrally in core.dryrun_option's callback; core.said counts the would/warn/error lines of the running command)
- `sync`, `assignment create`, `course ta`, and `course settings` end with one `summary:` line (`summary (preview):` in a dry run) counting the changes by kind plus the warnings and errors printed; after a real run `course init` and `assignment create` print a `next:` line naming the next step. the renamed meta commands set core.LEGACY and print none of the footer, summary, or next lines — their output stays exactly as it was; shared helpers pick their wording through meta._word/_heading/_sync_hint, so meta show/delete keep `CLASSROOM`, `delete classroom`, and `run: meta apply` while the new commands say course and print a runnable `gh-class-sak sync COURSE --org ORG --apply`. a grant github 404s is dropped from the action log, so the summary counts only what happened

# how courses and assignments are identified

github classroom is gone, so nothing may call `gh classroom` or the `/classrooms` and `/assignments` REST endpoints.

- user-facing text says COURSE, never classroom: help, messages, docs, and command names. the stored names keep the old word — the `classroom-meta` repo, `classroom.ini`, its `[CLASSROOM]` section — because renaming them would strand every existing org. internal identifiers (classroom_dir, …) may keep it too
- a github ORG hosts a set of courses
- a COURSE is a directory containing a `classroom.ini` in its org's `classroom-meta` repo, named by the normalized canvas course partial it maps to. the config's `[ORGS]` section lists the github orgs, one per line — the course list itself lives in classroom-meta, never in the config. the COURSE argument of `course`, `assignment`, and `sync` is always a course, never an org (core.resolve_course): matched against the course directories of `--org`, else of every configured org; an exact name beats partial overlaps; ambiguity is an error; no config and no `--org` is an error; an unmatched name that overlaps an org name says to pass it as `--org`. the `repos`/`canvas` COURSE argument keeps the lenient rule (core.resolve_classroom): a configured org by name first (no meta lookup), else a course directory in the configured orgs' classroom-meta repos; it is used verbatim as an org name when there is no config
- an ASSIGNMENT is one repo per student or group in a course, recorded as a `.tsv` file in the course directory, named by its basename. the classroom-meta repo is required: commands that read a course error out when the org has none — the message offers both readings, absent (pointing at `course init`) or private and invisible to the token, and names the token's identity, scopes, and likely fix; a repo that is there but records no courses, or that won't check out, says so instead. there is no prefix-inference fallback
- an assignment's repos are found by their name prefix (the prefix-assignment join) plus the recorded REPO_IDs
- a TEAM is the repo name with the assignment's repo prefix stripped off
- the default repo name joins the non-empty parts of the course prefix, the assignment, and the row NAME with `-` (the prefix is optional), cut off at github's 100-character limit; a row whose default name is already held by another row's repo — in any course in the org (the claims load every course dir) — takes the first free numbered name (`-2`, `-3`, …, NAME cut to fit) and the run warns which; a prefix+assignment that leaves no room for a NAME is an error (exit 1); a recorded REPO/REPO_ID always wins over the default name
- use PyGithub to talk to github and GitPython to talk to git. do not hand-roll requests sessions or pagination

# the classroom-meta repo

- each org may have a private repo named `classroom-meta` recording course state: one directory per course with `classroom.ini` and one `<assignment>.tsv` per assignment (NAME STUDENTS REPO REPO_ID). classroom.ini carries everything else: [CLASSROOM] optional prefix/template/settings, [TAS] one identity per line, [TEMPLATE] one ASSIGNMENT = REPO_URL per record, [GROUP_SETS] one ASSIGNMENT = SET per record. a legacy standalone `tas` file is still read and removed on the next save
- classroom.ini repo settings, all optional: `protection` (none or pr-review — default none, pr-review requires one approving review), `linear_history` (default true), `force_push` (default false)
- identities are written EMAIL/GITHUBID: both halves `joe@example.com/JoeDevExample`, email only `joe@example.com/`, github id only `/JoeDevExample`. legacy bare entries still parse (an @ means an email, anything else a github id), but the tool always writes the slash syntax
- in an assignment tsv the instructor supplies NAME and STUDENTS (comma-joined identities that get write access); a `/githubid` half is used directly, an email-only identity is resolved via canvas only (the profile's github link) — the github search api is never used. github's own route names (github.com/dashboard, settings, …; the RESERVED_GITHUB_NAMES set) are never ids: not recorded from canvas, unresolvable when recorded, bad-link in message-missing. the tool fills REPO (url) and REPO_ID (github's permanent numeric id) when it creates the repo, and never clobbers them on re-import
- `course init COURSE [--org ORG] [--canvas-course NAME]` records the literally-named new course; the org is the single `[ORGS]` entry, the partially-matched `--org`, or — with no config — the course argument itself. several configured orgs without `--org` is an error. an org missing from `[ORGS]` is added to the config (created if needed) so later commands need no `--org`; `meta init` doesn't. `--canvas-course` records the canvas course name in classroom.ini and canvas lookups prefer it over the directory name. a NEW course's prefix defaults to the github-safe course argument (`--prefix ""` opts out); a re-init keeps the recorded prefix and never backfills a prefixless course. init also creates the course's `COURSE-TAs` team (github slugs the name to lowercase; lookups use the slug) with the tas as members and read on the course's current repos — usually none yet. `--like OTHER` seeds a NEW course (an existing one is an error) with OTHER's tas, template, [TEMPLATE] records, and protection trio — never its prefix or assignments; explicit flags beat the copy
- `assignment create COURSE NAME (--roster FILE | --from-canvas) [--org ORG]` records the roster as assignment NAME (NAME.tsv), merging into an existing one, then brings only that assignment's repos in line: creates missing ones, invites missing collaborators, welcome-seeds, fixes protection drift, warns about unlisted collaborators (`--remove-unlisted-contributors` revokes), and grants the existing `COURSE-TAs` team read on them. other assignments' repos, the TA team's membership and other grants, and a missing TA team (warned: run sync) are sync's job. `--roster` and `--from-canvas` are exclusive; one of them or `--template` is required. a `--roster` file is a plain list (one identity per line → one repo per person, NAME = the github id, else the email's local part, made unique) or a NAME STUDENTS table (meta_store.parse_roster); a mixed or malformed file is an error naming the line, printed with an example of each format. `meta assign` keeps the table-only parse_students_tsv
- `assignment create --template REPO_URL` validates the url with git ls-remote (exit 2 when unreachable), records it in [TEMPLATE] for the assignment, and new repos for that assignment are seeded from a shallow clone of it pushed as a single fresh commit (no template history) on the repo's default branch. the [TEMPLATE] record takes precedence over the course-wide `template` for its assignment. without a roster it records the template alone; an unreachable template at realize time errors, deletes the empty shell, and exits 1 so a re-run retries
- `assignment create COURSE NAME --from-canvas [--canvas-group SET]` builds the roster from canvas: one row per enrolled person (students, instructors, and TAs), NAME = the person's github-safe name (accents stripped, invalid chars become `-`), entry = their EMAIL/GITHUBID identity with both halves as far as canvas knows them. with `--canvas-group`, one row per group in that canvas group set, and the set's name is recorded per assignment in classroom.ini `[GROUP_SETS]`; a group member is matched to an enrollment by canvas user id — two enrolled people can share a name. only a member canvas returns without an id falls back to its normalized name, and only when exactly one enrolled person has that name; several namesakes, or a supplied id that isn't on the enrollment list, is an error (unresolvable), never a guess. a group with any member that couldn't be matched keeps its recorded students unchanged (a warn says so) rather than merging the partial row, so a re-import never erases or later revokes a real student a recorded row whose person or group is gone from canvas is warned about and kept; `--remove-dropped` (only valid with `--from-canvas`) removes the row instead — its repo is never deleted (a warn names each repo left behind; the next sync revokes the TA team's read on it), and an enrollee whose canvas entry has neither email nor github link is never treated as dropped. namesakes (two people, or two groups, with one github-safe name) get numbered NAMEs (`Jose-Nunez`, `Jose-Nunez-2`) so neither replaces the other in the merge (meta_store.uniquify_names); people are told apart by a shared email or github half with the recorded rows, so the numbering survives roster reordering, a departed namesake's NAME is never reused, and a name with no namesake keeps its plain NAME even when its identity changes
- `sync (COURSE | --org ORG)` makes the org match the meta — the named course only, or every course in `--org`. per course and assignment: creates missing repos (privately, from the template when set), each course's TAs go into a `COURSE-TAs` team added as a read collaborator on that course's student repos across all its assignments, students get write on their repos. unlisted non-admin collaborators (and their pending invitations) are warned about and left alone; `--remove-unlisted-contributors` revokes them instead. admins are never touched either way. a grant github 404s (the recorded login doesn't exist — e.g. a pasted github.com/dashboard) is a loud per-person error, never a crash: the rest of the run completes and exits 1
- `sync`/`assignment create` put the effective repo settings on each repo's default branch. a repo created without a template starts empty, so both commands seed an empty repo with a `WELCOME.md` initial commit (`Welcome to COURSE! You will submit your assignments here using git commit and git push.`) — the branch exists and the protection lands in the same run. the all-off trio (none/false/true) skips the protection API entirely and existing protection is never removed; free org plans can't protect private repos (warn, don't fail); a protection write replaces hand-set extras like status checks
- `course ta add|remove COURSE IDENTITY...` edits [TAS] and reconciles the `COURSE-TAs` team in one run (membership, and read on the course's repos). add warns about a current TA (either half matching, case-insensitive); remove matches either half and errors (exit 2, nothing changed) on someone who isn't a TA
- `course settings COURSE` prints the effective protection/linear_history/force_push and template; with `--protection`, `--[no-]linear-history`, `--[no-]force-push`, or `--template` (`""` clears) it records the change and puts the protection on every recorded repo (welcome-seeding empty ones) in the same run. a value equal to the effective one is nothing to do. its dryrun pair has no callback: the banner prints only when something is being changed (core.announce_dryrun)
- the audit trail (gh_class_sak/audit.py): every real change to who can reach a course's repos — create/adopt repo, invite, revoke, cancel invitation, add to / remove from TAs team — is recorded via `_perform(..., logged=(course_dir, action, repo, who, why))`, only after the change succeeded (a grant github 404s logs nothing), and appended to `<course>/audit.log` in classroom-meta (tab-separated TIME BY COMMAND ACTION REPO WHO WHY; `.log`, never `.tsv`, which would read as an assignment) by audit.flush before the run's commit (meta._commit_audit where a command has no commit of its own). WHY names the tsv row and identity, and says "(github id from the canvas profile link)" when the id came from canvas; TA changes cite the [TAS] line. BY is the token's login. dry runs log nothing; the buffer resets per invocation. _open_meta binds the checkout (audit.bind), and the first record hooks the click context's close: a command that stops early (any exception or exit before its flush) still commits the entries for changes that happened — only the audit.log paths (ms.commit_paths_and_push), never the run's half-done roster edits — and if even that fails, prints them
- `course audit COURSE` (read-only, exit 1 on a problem): someone with access or an invitation no row lists (rows with unresolved identities skipped); one login on rows for different people; with canvas (meta._canvas_people), a login that shares no part of the enrolled person's canvas name — rows cover students, instructors, and TAs, so messages say person, never student (meta._looks_like, words split Unicode-aware so any script counts: no canvas word in its github name, and no 3+-letter canvas word inside its login or its github name run together — github names are free-form, so first names, nicknames, and handles must pass; a stricter fuzzy match flagged 18 of ~150 real accounts wrongly), or a recorded github half the canvas profile no longer links. each problem prints its fix. a real `sync` (not a dry run, not the legacy `meta apply`) prints it for every course it synced, before the summary line, without changing sync's exit status
- `course status COURSE` (read-only): per assignment, rows with a repo and students accepted / invited / not invited, the TAS TEAM line, then a to-do list pairing each gap with the command that closes it, or `all set`
- `course delete COURSE [--delete-repo]` shows the course's recorded info then confirms: a simple yes for an empty course, typing the full name of one of its assignments otherwise. removes the course directory from classroom-meta; `--delete-repo` (default off) also deletes the recorded github repos. the tas team is left alone. standard dryrun pair, confirmation prompts run in both modes
- `course list [COURSE] [--org ORG]` prints one table row per recorded course — COURSE, PREFIX, TAS (count), and ASSIGNMENTS as name(teams) — straight from the classroom-meta repos with no live-org checks. without arguments it walks every `[ORGS]` org; `--org` names one org, COURSE a single course. empty cells show `-`
- `course show COURSE` checks the recorded state against the live org: each student is marked ✅ (collaborator), 📧 (invited, not accepted), or ❌ (not a collaborator) — rows without a repo stay unmarked — and a TAS TEAM line reports whether the `<course>-TAs` team matches the [TAS] section (missing/extra members listed)
- the pre-rename commands still work unchanged but are hidden from --help: `meta init/list/show/delete/assign/apply` and `classrooms`. at a tty each prints which command replaced it (core.renamed); pipes and scripts see nothing new. `meta assign` still converges the whole classroom, and `meta list`/`classrooms` keep their CLASSROOM output formats
- discovery honors recorded REPO_IDs, so renamed repos stay tracked; the repos ASSIGNMENT argument selects an assignment tsv by case-insensitive substring, exact name wins over substring hits, and a name matching in several classrooms is an error

# getting information about instructors and students

### listing student and instructor names, emails, and relationships

- find students and instructors of a section using this graphQL. instructors of a student share a courseSectionId with that student
    ```
    query MyQuery {
      course(id: "COURSEID") {
        name
        enrollmentsConnection {
          nodes {
            role {
              name
            }
            user {
              id
              name
              email
            }
            courseSectionId
          }
        }
      }
    }
    ```

### determine github information for students and instructors

find the github ids of all the students and instructors using the canvas REST API to get the profile for the given user id and look for the github link. only account links count (`github.com/NAME`, optionally ending in `/`, a query, or a fragment) — a link into a repo (`github.com/OWNER/REPO/…`) names the repo's owner, often someone else, and is never read as the student's account. a profile link titled "github" wins, then other profile links in order, then the bio (repos.extract_github_username)

# subcommands

- canvas message-missing: takes a COURSE and ASSIGNMENT; sends a canvas conversation to each enrolled student stranded on the way to their assignment repo, in three categories — no-link (no github link on the canvas profile), bad-link (the linked github account doesn't exist), invited (an unaccepted repo invitation, message names the repo url). collaborators are never messaged; a student with a working github account but neither repo access nor a pending invitation is a loud error to the instructor (exit 1) pointing at `sync`, never a message to the student — errors are held and printed at the end of the run so the progress bars stay intact, and a canvas send failure joins them (exit 1) instead of aborting the remaining sends. the sending loop only shows a progress bar under --no-dryrun; a dry run's would-lines are the output. canvas's student-view Test Student (enrollment type StudentViewEnrollment, role StudentEnrollment) is not a person: excluded from every roster the tool builds — messaging, --from-canvas rows, repos missing. needs the canvas config. standard dryrun pair; the dry run lists recipients and prints the full message texts (templates live at the top of commands/canvas.py). each send is a new conversation (force_new), never an append to an old thread
- help-me-setup: explain the config file (print a template when none exists) and verify the setup: github token, each configured org and its classroom-meta repo, canvas credentials. read-only, exit 1 when something needs attention. it also flags a classic token without the `repo` scope (with the `gh auth refresh` fix). `--create-config` — or a yes to the offer at a tty when the config is missing — asks for the org and optional canvas url/token and appends only the missing sections, never overwriting; a file holding a canvas token is chmod 600. its all-good ending points at `completion`
- migrate-github-classroom: takes an ORG; scans its Classroom-era repos (named ASSIGNMENT-TEAM), infers the assignments from shared name prefixes, then prompts per assignment for the course it belongs to (blank skips) and its name (default: the prefix). records one tsv per assignment under the chosen course's dir — collaborators as students, repo url and permanent id filled in. a login with write on every one of a course's repos (>=2 repos) is a TA: excluded from STUDENTS and recorded in the course's [TAS] section instead — unless everyone is on every repo (one group owning all the repos), which warns and records everyone as students. when every assignment name is a `-`-suffix of its inferred repo prefix, the shared head is recorded as the new course's `prefix` (teams always strip the inferred repo prefix, whatever the assignment is named). adds the org to the config's [ORGS] when missing (creating the file if needed); merges like `assignment create` and never clobbers recorded repos; standard dryrun pair with prompts asked before the preview
- course list never enumerates the orgs the token belongs to: no COURSE, no `--org`, and no `[ORGS]` is an error
- repos list: takes a COURSE and ASSIGNMENT and lists each repo
    - output is space-padded columns with a header row: TEAM always, then REPO, MEMBERS, INSTRUCTORS, GROUP depending on flags; the last column is never padded
    - members are comma-joined repo collaborators excluding admins; `--name`/`--email` annotate each as LOGIN(NAME,EMAIL)
    - if the `--alt` flag is given, any alternative repo names (previous names for the repo) will be shown as an extra column
- repos members: list the members of each repo with names and emails mined from commit history
- repos missing: list canvas students, or canvas groups with `--group`, that have no repo
- repos clone: clone or fast-forward every repo for an assignment. pass the token to git through the environment so it never lands in argv, the clone url, or `.git/config`. `--before DEADLINE` (a bare date = the end of that day, or YYYY-MM-DD HH:MM; local time) leaves each clone detached at the commit its default branch held after its last push at or before it, by github's push record — GET /repos/{owner}/{repo}/activity, read through PyGithub's PaginatedList with github_api.BranchPush (github_api.pushed_before), never commit dates, which students' machines set. a commit a later force push took off the branch is fetched by id (git_ops.checkout_commit). AT reads `SHA (pushed …)`; no push before the deadline (or the branch deleted then) is a loud error and the clone stays at its latest; a repo github has no push record for, or definitively won't share one for (404, 410, a 403 that isn't a rate limit), falls back to commit dates (git_ops.checkout_before) with a warning, and AT reads `(committed …)`; any other failure (5xx, rate limit, bad credentials) raises RuntimeError from pushed_before and is that repo's error — never a fallback to student-set dates. tests drive branch_pushes through the real PaginatedList with a fake requester serving github-shaped pages. clone_or_update re-attaches a detached checkout to its branch before pulling
- repos update: takes a file with the same format as `repos list` that will update the repo with the give members and admins
    - if any of the ids are emails, first resolve the email to the github id. print a noticeable error if the email does not resolve

- completion [bash|zsh|fish]: prints click's completion script (shell from $SHELL when omitted); its help shows the startup-file line per shell
- demo [COMMAND...]: runs the command against the invented cs101-fall course inside demo_world(with_config, with_git) in a temp dir deleted after — github faked, demo repos backed by local bare gits so clone works, canvas absent. no command prints an intro. never touches the real config, github, or canvas
- every visible command's --help ends with an `Examples:` block (after `\b`); a test walks the command tree and fails any command without one
